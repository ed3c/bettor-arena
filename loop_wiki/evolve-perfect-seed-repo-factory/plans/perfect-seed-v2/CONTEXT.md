# Canonical terms

| term                    | canonical meaning                                                                                                                                        |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| perfect seed            | A minimal, reusable, evidence-bearing repo architecture; an optimization target, never an automatic PASS label.                                          |
| ontology                | Versioned schemas and registries defining legal entities, relations, skills, prompts, and oracles. Concrete execution data is not ontology.              |
| initial seed            | The hash-bound template-owned and ontology-owned file set declared by `seed-manifest.json`.                                                              |
| domain run modification | A Work-Item, source/evidence artifact, user-domain file, receipt, projection, or prompt created after materialization.                                   |
| seed reset              | Reconstructing the initial seed from the manifest while preserving/exporting non-seed ownership classes; never filename guessing or deletion.            |
| Work-Item               | Local canonical identity for one admitted terminal slice and at most one candidate molecular commit.                                                     |
| terminal slice          | A bounded objective, invariant set, allowed-path closure, oracle set, and candidate delivery edge.                                                       |
| capability packet       | Immutable, content-addressed statement of intent, architecture closure, scope, oracles, CQ-0, prompts, and promotion rules.                              |
| terminal envelope       | One-attempt execution authorization binding a capability packet to HEAD/tree, lease, allowed paths, retry budget, and output contracts.                  |
| intended graph          | Normative architecture nodes and edges declared by the seed.                                                                                             |
| observed graph          | Read-only projector output bound to an exact repo commit/tree and observation adapters.                                                                  |
| conformance projection  | Difference between intended and observed graphs, including blind spots; disposable and rebuildable.                                                      |
| complete perception     | Coverage of the declared observation closure with explicit blind spots. It does not mean universal knowledge.                                            |
| CQ-0                    | Low-cost synchronous candidate gate: minimum lineage, format, typed lint, affected strict TypeScript closure, dependency boundary, and focused behavior. |
| CQ-1                    | Deferred full code-quality axis bound to an immutable candidate and profile.                                                                             |
| Production Use          | Deferred physical journey evidence such as race, non-silent failure, cancellation, and resource lifecycle.                                               |
| candidate commit        | One molecular commit after CQ-0; implemented but neither verified nor admitted.                                                                          |
| attestation             | Immutable observation bound to candidate commit/tree, profile, oracle, evidence, and claim boundary.                                                     |
| Forgejo projection      | Recoverable issue/comment/readback view of local Work-Item and verification facts; never identity or evidence SSOT.                                      |
| fixed prompt            | Versioned template/contract context selected before execution.                                                                                           |
| automatic prompt        | Deterministically derived next-action or repair context from current physical projection.                                                                |
| emergent prompt         | Explicitly surfaced new unknown, drift, failure, or branch context; never hidden chat state.                                                             |
| molecular index card    | Seven stable repo-relative commit fields used for retrieval; detailed evidence is indirect and hash-bound.                                               |
| RAG index               | Disposable retrieval projection over registries, commit cards, attestations, and projections; deletion cannot change gates.                              |
| admitted                | A derived state requiring current physical evidence plus an explicit human admission artifact.                                                           |
