# Exchange formats

## Input packet

`perfect-seed-input@1.0.0` requires packet id/state, source kind/path, task,
fixed and emergent context, `source_refs`, and `required_before_seed_admit`.
Only admitted packets may materialize a repo.

`source_refs` is a required non-empty array; each entry is
`{repo, commit (7-40 lowercase hex), path (repo-relative, no traversal), anchor}`.
Validation checks shape only and never dereferences `repo`; standing
validate/build/verify gates read zero sibling checkouts. The explicit audit is
`cli.ts resolve-refs --packet <p> --peer <absolute-path>`: it checks each
commit exists and each path is tracked at that commit via local git plumbing.
Without `--peer` it prints `NOT_RUN` and exits `2` — never `PASS`.

Refs carry a tri-state `refs_status` owned by `src/contracts.ts`:

- `declared` — shape-validated, never audited against a peer;
- `sentinel` — the packet carries the migrate-injected `unknown` placeholder;
- `resolved` — granted only when `resolve-refs --peer` succeeded and wrote
  `<packet>.resolve-receipt.json` (`perfect-seed-resolve-receipt@1.0.0`) whose
  `packet_sha256` still matches the packet bytes. Standing gates read that
  local receipt only — still zero sibling checkouts. `cli.ts refs-status
--packet <p>` emits the status JSON that `trigger.sh` relays verbatim.

## Schema replay

`src/migrate_packet.ts` is the only current migration edge:
`perfect-seed-input@0.1.0` → `perfect-seed-input@1.0.0`. It adds explicit
context and human-gate fields but does not auto-admit a draft packet. A legacy
packet without `source_refs` receives the marked sentinel
`{repo:"unknown", commit:"0000000", path:"unmigrated/unknown", anchor:"pre-source-refs"}`
(the exported `SENTINEL_SOURCE_REF` in `src/contracts.ts`); validate accepts
it, but route-result and lineage record `refs_status:"sentinel"` so an
unmigrated packet never fakes an anchor.

## Result formats

- source/IR/lineage schemas are versioned in their files;
- call plan contains exactly twenty calls and dependency ids;
- call results are JSONL with input/output SHA-256;
- route result is generated by `trigger.sh`, carries `source_refs` and the
  tri-state `refs_status`, and ends at human-required; the same refs and
  status flow through the reduced IR `source` record into the generated repo's
  `data/lineage.json`, and the verifier asserts `data/source.json` and
  `data/lineage.json` agree on both;
- `perfect-seed-fast-quality-receipt@1.0.0` records gate-input hashes,
  per-stage commands, exit codes, elapsed time, stdout/stderr tails, and
  fail-fast `not_run` stages; its claim boundary is preflight-only;
- baseline updates require a reviewed/admitted governance packet.

Paths are passed as structured argv. No packet contains a shell command.
