judge-loop-chooser 邊界：清晰（有條件）

flywheel／adlc 技術等價物吸收後，chooser 的物理邊界仍然成立——條件是守住下面三條扭曲風險的護欄。其 grounding 三態（技術實現等價物／candidate／[推論]）即語意真相機制：路由結果永遠帶態標，禁把 candidate 說成等價物。

邊界內（chooser 擁有）

  • 可判 deliverable（DR 報告／Path-B 精煉／覆蓋矩陣）→ 驗證標準＋獨立性 tier（T0–T3）路由
  • fit-to-plan 選組件（如 ds-workflow 換件），但六閘不因換件降級
  • 只路由＋SURFACE；grounding 三態錨 automate.js COMPLETENESS_RUBRIC

邊界外（禁路由進來）

  • 代碼產物 → code-review（本地版明言無 code/sandbox 判決表）
  • 小迴圈畢業判 → wiring 三態＋T0＋人閘（02 spec 擁有）
  • 每輪 keep/discard → 迴圈內 verify.sh exit code（D6）
  • semantic 畢業判官 → 08 evals.json＋fresh zero-context subagent（D6.1）
