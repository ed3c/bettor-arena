# Architecture Decision Records

`docs/adr/` stores admitted decisions whose trade-offs must remain reviewable after implementation changes.

Each ADR should include:

- status and date;
- decision subject;
- context and rejected alternatives;
- consequences and rollback boundary;
- affected module IDs and interfaces;
- evidence or canaries required before promotion.

An ADR is not a proof receipt and must not turn an unexercised path into PASS.
